# S3 storage for inputs and outputs

Serverless jobs return results either inline (`OUTPUT_MODE=base64`) or as links to files the worker uploaded
(`OUTPUT_MODE=s3`). Base64 is fine for images. **Use S3 for video**: Runpod limits how big a job result can be,
and a 20-second 1080p clip is far above it. The same bucket can also hold your inputs (`s3://bucket/key` URLs
are accepted for every picture, video and audio input).

Any S3-compatible service works. Three common choices:

## Option 1: the Runpod network volume's S3 API (no extra account)

Some Runpod datacenters expose network volumes through an S3-compatible API, so outputs land on the volume you already pay for.

1. Runpod console → **Settings → S3 API Keys → Create**. Copy the access key and the secret (shown once).
2. Look up your volume's **datacenter id** (for example `eur-is-1`) and **volume id** under **Storage**.
3. Set on the endpoint:

| Variable | Value |
|---|---|
| `OUTPUT_MODE` | `s3` |
| `S3_ENDPOINT` | `https://s3api-<datacenter-id>.runpod.io` (e.g. `https://s3api-eur-is-1.runpod.io`) |
| `S3_REGION` | `<datacenter-id>` (e.g. `eur-is-1`) |
| `S3_BUCKET` | the network volume id |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | the key pair from step 1 |

Files are written under `outputs/<job id>/` on the volume. Runpod's volume S3 does **not** serve presigned links
(they answer 403), so for an endpoint on `*.runpod.io` the handler returns `s3://<volume id>/outputs/<job id>/<file>`
instead, and the app fetches the file itself: in the app, **backend pill → Serverless → Volume S3 keys**, paste the
same access key and secret. (`S3_PRESIGN=1` / `0` overrides the detection.) Check Runpod's docs for which datacenters
offer the S3 API and its current limits.

## Option 2: Cloudflare R2 (no egress fees)

1. Cloudflare dashboard → **R2 → Create bucket**, e.g. `kitty-outputs`.
2. **R2 → Manage API tokens → Create API token** with *Object Read & Write* on that bucket. Copy the access key id,
   the secret and the S3 endpoint `https://<account-id>.r2.cloudflarestorage.com`.
3. Optional, for public links without expiry: **bucket → Settings → Public access** (an `r2.dev` URL or your own domain),
   then set `S3_PUBLIC_URL` to that base URL.
4. CORS (only if a browser uploads straight to the bucket): bucket → Settings → CORS policy:

```json
[{"AllowedOrigins": ["*"], "AllowedMethods": ["GET", "PUT", "HEAD"], "AllowedHeaders": ["*"], "MaxAgeSeconds": 3600}]
```

| Variable | Value |
|---|---|
| `OUTPUT_MODE` | `s3` |
| `S3_ENDPOINT` | `https://<account-id>.r2.cloudflarestorage.com` |
| `S3_REGION` | `auto` |
| `S3_BUCKET` | `kitty-outputs` |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | the token's key pair |
| `S3_PUBLIC_URL` | optional, e.g. `https://pub-xxxx.r2.dev` |

## Option 3: AWS S3

1. **S3 → Create bucket** (keep *Block all public access* on; the handler returns presigned links).
2. **IAM → Users → Create user**, attach an inline policy:

```json
{"Version": "2012-10-17", "Statement": [{"Effect": "Allow",
  "Action": ["s3:PutObject", "s3:GetObject", "s3:ListBucket"],
  "Resource": ["arn:aws:s3:::kitty-outputs", "arn:aws:s3:::kitty-outputs/*"]}]}
```

3. **Security credentials → Create access key** (application running outside AWS).
4. Add the CORS rule from option 2 if browsers upload directly.

| Variable | Value |
|---|---|
| `OUTPUT_MODE` | `s3` |
| `S3_ENDPOINT` | leave empty |
| `S3_REGION` | the bucket's region, e.g. `eu-central-1` |
| `S3_BUCKET` | `kitty-outputs` |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | the access key pair |

## Keep it tidy and safe

- Keys belong in the endpoint's environment variables or Runpod secrets, never in the repo or in job inputs.
- Add a lifecycle rule (R2 and AWS both support it) that deletes `outputs/` after N days.
- `S3_PREFIX` changes the folder (default `outputs`), handy when several endpoints share one bucket.

## How long outputs are kept

The handler deletes outputs older than `RETENTION_DAYS` (default 3) under `S3_PREFIX` when a job starts, at most once every 10 minutes per worker. No bucket lifecycle rule or scheduled job is needed; `RETENTION_DAYS=0` keeps everything.
